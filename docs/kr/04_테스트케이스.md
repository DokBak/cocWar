## 1. 테스트 방법

### 1.1 자동 테스트의 종류
| 종류 | 대상 | 설명 |
|---|---|---|
| 단위 테스트 | 모델, 계산 함수 | 함수 하나에 값을 넣고 결과가 맞는지 확인한다 |
| 서버 테스트 | 서버 라우트 | 실제 서버를 띄우지 않고 요청 처리 함수에 가짜 요청을 넣어 응답을 확인한다 |
| 위젯 테스트 | 앱 화면 | 화면을 테스트 환경에서 그려 글자, 버튼, 이동, 위치를 확인한다 |

### 1.2 가짜 데이터를 쓰는 이유
- 공식 API는 토큰과 등록한 IP가 있어야 하고, 데이터가 계속 바뀐다. 그래서 테스트는 실제 API를 부르지 않는다.
- 서버는 `server/test/app_test.dart`의 `FakeApi`, 앱은 `apps/mobile/test/support/fake_api.dart`의 `FakeApi`로 정해진 응답을 돌려준다.
- 클랜전은 `war_fixture.dart`(2 대 2 전쟁), 리그전은 `cwl_fixture.dart`(3클랜, 3라운드)의 고정 데이터를 쓴다.
- 요청 횟수도 센다. 오류가 나도 같은 요청이 반복되지 않는지 확인하기 위해서다(NFR-03).

### 1.3 실행 명령
```
cd packages/coc_models && dart analyze && dart test
cd server && dart analyze && dart test
cd apps/mobile && flutter analyze && flutter test
```
`analyze`는 코드를 실행하지 않고 문법 오류나 잘못된 사용을 찾는 정적 분석이다.

## 4. 수동 확인 항목
자동 테스트로 확인하기 어렵거나 실제 환경이 필요한 항목이다.

| ID | 확인 내용 | 방법 | 시기 |
|---|---|---|---|
| M-01 | 실제 화면 전체 흐름(검색 → 클랜 → 플레이어 → 클랜전) | 서버와 웹 앱을 띄워 브라우저에서 확인 | 기능 변경 때마다 |
| M-02 | 홈의 비공식 고지 문구 | 웹 앱 홈 화면 확인 | 릴리스 전 |
| M-03 | 다크 테마와 시스템 테마 전환 | 설정에서 테마를 바꿔 확인 | 릴리스 전 |
| M-04 | 실제 토큰·IP로 서버가 공식 API를 부르는지, 앱 빌드에 토큰이 없는지 | 서버 실행 후 `curl http://localhost:8080/clans/%232LCQYV0VL`, `curl http://localhost:8080/players/%232PLCLPYV` | 서버 환경이 바뀔 때 |
| M-05 | 커밋에 `.env`·토큰·게임 이미지가 없는지 | 푸시 전 `git status`, `git diff --cached --name-only` | 푸시할 때마다 |
| M-06 | 리그전 실제 데이터(순위, 라운드, 멤버 성적, 버튼) | 리그전 기간(매월 초)에 리그전에 참가한 클랜으로 확인 | 2026년 11월 시즌 |
| M-07 | 동률 기준 "총 파괴율"이 게임 화면 값과 같은지 | M-06 때 게임 화면과 비교 | 2026년 11월 시즌 |

웹 실행 명령:
```
cd server && dart run bin/server.dart
cd apps/mobile && flutter run -d web-server --web-hostname localhost --web-port 5173 --dart-define=API_BASE_URL=http://localhost:8080
```
