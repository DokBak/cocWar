## 1. タグ処理 (共通)
`packages/coc_models/lib/src/tag.dart`

| 関数 | 動作 |
|---|---|
| `normalizeTag(input)` | 空白を除去 → 先頭の `#` または `%23` を除去 → 大文字に変換 → 英字の `O` を数字の `0` に置換 → 先頭に `#` を付ける。例: ` 2lcqyvovl` → `#2LCQYV0VL` (`#` なし、小文字、英字の O をまとめて直す) |
| `isValidTag(tag)` | `#` の後ろが `0289PYLQGRJCUV` の文字だけで 3〜12 文字かを確認する |

アプリ(検索、画面のアドレス)とサーバー(すべてのルート)が同じ関数を使う。未確定のリーグ戦の対戦タグ `#0` はこの検査を通らない。

## 2. サーバー
`server/lib/src/app.dart`、`server/lib/src/coc_api_client.dart`、`server/bin/server.dart`

### 2.1 ルート
| 自前サーバーのアドレス | 公式 API のアドレス | クエリ | キャッシュ | 要件 |
|---|---|---|---|---|
| `GET /health` | - | - | - | - |
| `GET /clans/<tag>` | `/clans/{tag}` | - | 2 分 | FR-09 |
| `GET /clans/<tag>/warlog` | `/clans/{tag}/warlog` | `limit`、`after`、`before` | 5 分 | FR-12 |
| `GET /clans/<tag>/currentwar` | `/clans/{tag}/currentwar` | - | 1 分 | FR-18〜21 |
| `GET /clans/<tag>/currentwar/leaguegroup` | `/clans/{tag}/currentwar/leaguegroup` | - | 5 分 | FR-22〜26 |
| `GET /clanwarleagues/wars/<warTag>` | `/clanwarleagues/wars/{warTag}` | - | 1 分 | FR-24 |
| `GET /clans/<tag>/capitalraidseasons` | `/clans/{tag}/capitalraidseasons` | `limit` | 2 分 | FR-11 |
| `GET /leagues` | `/leagues?limit=100` | - | 24 時間 | FR-03、FR-09 |
| `GET /players/<tag>` | `/players/{tag}` | - | 2 分 | FR-14〜17 |

- 処理の順序: タグの正規化 → 形式の検査(失敗したら 400、公式 API は呼ばない) → キャッシュの確認 → 公式 API の呼び出し → 成功応答のみキャッシュに保存 → JSON で応答
- キャッシュのキーは `名前|正規化したタグ|クエリ文字列` である。クエリが異なれば別々に保持する。
- 応答ヘッダーに `cache-control: public, max-age=<キャッシュ秒数>` を付ける。
- すべての応答に CORS ヘッダー(`access-control-allow-origin: *`)を付け、`OPTIONS` リクエストにはすぐ 200 で応答する。Web アプリが別アドレスのサーバーを呼び出せるようにするためである。

### 2.2 エラー変換
| 公式 API | 自前サーバーの応答 | `reason` | 備考 |
|---|---|---|---|
| 403 `accessDenied` | 403 | `accessDenied` | 非公開の戦争ログなど |
| 403 その他 (`accessDenied.invalidIp` など) | 502 | `upstreamAuth` | サーバーのトークン・IP 設定の問題。ログを残す |
| 400 | 400 | 公式の `reason` または `badRequest` | |
| 404 | 404 | `notFound` | リーグ戦の期間外も 404 |
| 429 | 429 | `rateLimited` | |
| 503 | 503 | `inMaintenance` | |
| その他 | 502 | `upstreamError` | ログを残す |
| サーバー内の予期しない例外 | 500 | `internalError` | ログを残す |

応答本文の形式: `{"reason": "...", "message": "..."}`

### 2.3 キャッシュ (`server/lib/src/ttl_cache.dart`)
- 項目ごとに有効期限を持つメモリキャッシュ。最大 1000 件。
- 満杯になったら期限切れの項目を先に削除し、それでも満杯なら最も古く入れた項目から削除する。

### 2.4 起動
- 設定は環境変数を優先し、なければ `.env` を読む。`COC_API_TOKEN` がなければ終了コード 64 で終了する。
- `PORT`(既定 8080)ですべてのアドレス(0.0.0.0)からリクエストを受ける。リクエストごとにログを残す。

## 3. 共通モデル
`packages/coc_models/lib/src/` (freezed + json_serializable、生成ファイルもコミットする)

| ファイル | モデル | 使用箇所 |
|---|---|---|
| `clan.dart` | `Clan`、`ClanMember` | クラン画面、ホームの履歴 |
| `player.dart` | `Player`、`PlayerClan`、`PlayerItem`、`Achievement` | プレイヤー画面 |
| `war_log.dart` | `ClanWarLog`、`ClanWarLogEntry`、`WarClan` | 戦争ログ |
| `current_war.dart` | `CurrentWar`、`CurrentWarClan`、`WarMember`、`WarAttack`、`WarState` | クラン戦、リーグ戦の対戦 |
| `league_group.dart` | `ClanWarLeagueGroup`、`LeagueGroupClan`、`LeagueGroupMember`、`LeagueRound`、`LeagueGroupState` | リーグ戦 |
| `capital_raid.dart` | `CapitalRaidSeasons`、`CapitalRaidSeason`、`CapitalRaidMember`、`RaidState` | メンバーカードの襲撃攻撃権 |
| `common.dart` | `BadgeUrls`、`IconUrls`、`Label`、`League` | 共通 |
| `paging.dart` | `Paging`、`Cursors` | 一覧の応答 |
| `coc_date_time.dart` | `CocDateTimeConverter` | `20261013T100000.000Z` 形式 ↔ UTC 時刻 |

- すべてのフィールドは空でもよい(nullable)ようにし、リストは既定値を空のリストにする。公式 API がフィールドを省いて送ってもアプリが止まらないようにするためである。
- 未知の状態値は `unknown` として読む(`WarState`、`LeagueGroupState`、`RaidState`)。
- 戦争の応答のタウンホールのフィールドは `townhallLevel`(h が小文字)のため、`@JsonKey` で名前を合わせる。

## 4. アプリ

### 4.1 共通 (`apps/mobile/lib/core/`)
| ファイル | 内容 |
|---|---|
| `api_client.dart` | サーバーの呼び出し(dio、接続 10 秒・応答 20 秒のタイムアウト)。エラーを `ApiErrorKind` に変換する |
| `providers.dart` | `apiClientProvider`、`sharedPreferencesProvider`、設定(言語・テーマ)、最近の検索(10)、お気に入り(100)、`noAutoRetry` |

アプリのエラー種別(`ApiErrorKind`):

| サーバーの応答 | 種別 | 画面の文言 |
|---|---|---|
| 400 | `invalidTag` | 見つからない |
| 403 `accessDenied` | `privateLog` | 戦争ログが非公開 |
| 404 | `notFound` | 見つからない |
| 429 | `rateLimited` | リクエスト過多 |

### 4.2 画面ごとのデータ (Provider)
Provider はデータを取得し、ローディング・エラーの状態を管理する Riverpod の単位です。画面を閉じると破棄されるよう(`autoDispose`)にしています。

| 画面 | Provider | 内容 |
|---|---|---|
| クラン | `clanProvider(tag)` | クラン情報 |
| クラン | `warLogProvider(tag)` | 戦争ログからリーグ戦の記録を除いた一覧。ページはアプリで 10 件ずつ分ける |
| クラン | `latestRaidProvider(tag)` | 最新の襲撃 1 件(`limit=1`)。エラーは null(その欄だけ隠す) |
| プレイヤー | `playerProvider(tag)` | プレイヤー情報 |
| プレイヤー | `levelCapsProvider`、`itemGroupsProvider`、`gameAssetsProvider` | レベル表、分類表、取得済みの画像一覧 |
| クラン戦 | `currentWarProvider(tag)` | 現在のクラン戦 |
| ボタン | `ongoingWarProvider(tag)` | 準備日・戦闘日のときだけ戦争、それ以外とエラーは null |
| ボタン | `ongoingLeagueProvider(tag)` | リーググループが準備日・戦闘日のときだけグループ、それ以外とエラーは null |
| リーグ戦 | `leagueGroupProvider(tag)`、`cwlWarProvider(warTag)` | グループ、対戦一つ |
| リーグ戦 | `cwlSeasonProvider(tag)` | グループを取得した後、`#0` を除くすべての対戦をまとめて取得する(最大 7 ラウンド × 4 対戦) |
| 共通 | `clockProvider` | 現在時刻(テストで固定) |

- 「情報を見る」ボタンは、通常の戦争の取得が**終わって**戦争がないときだけリーググループを取得する。取得中に先に呼ばないことでリクエストを節約する。

### 4.3 計算ルール
| ルール | 場所 | 内容 |
|---|---|---|
| タグ入力 | `tag.dart` | 1 章を参照 |
| メンバーの並び順 | `clan/clan_members.dart` | 役職(リーダー → サブリーダー → 長老 → メンバー) → タウンホールの高い順 → 名前(大文字・小文字を区別しない) → タグ |
| リーグ戦の記録の除外 | `clan/clan_providers.dart` | 結果がなく 1 人あたりの攻撃が 1 回のログ項目はリーグ戦とみなし、戦争ログから除く |
| 襲撃の攻撃権 | `clan/capital_raid_providers.dart` | 全体 = `attackLimit + bonusAttackLimit`。襲撃一覧にないメンバーは `0/5`。攻撃記録はあるのにメンバー一覧が空なら表示しない |
| 勝敗の見通し | `war/war_outlook.dart` | 星 → 破壊率の順で勝敗を決める。残り攻撃 = チームサイズ × 1 人あたりの攻撃 − 使用した攻撃。獲得できる星 = 相手の各基地の `3 − これまでの最高の星` の合計。必要な星 = 星の差 + 1。相手の残り攻撃は反映しない推定である |
| 対戦の向きの調整 | `cwl/cwl_stats.dart` `orientTo` | 自クランが `opponent` にいれば `clan` と入れ替える。リーグ戦の応答にない `attacksPerMember` は 1 で補う |
| リーグ順位 | `cwl/cwl_stats.dart` `cwlStandings` | 戦闘日・終了の対戦だけを数える。点数 = 星の合計 + 終了した対戦の勝利 × 10。同じなら合計破壊率(対戦ごとの破壊率 × チームサイズの合計)の高い順。星と破壊率がすべて同じなら引き分け(ボーナスなし) |
| メンバー成績 | `cwl/cwl_stats.dart` `cwlMemberStats` | 戦闘日・終了の対戦だけを数える。出場ラウンド、攻撃数、星、星3の数、平均破壊率(攻撃あたり)。星 → 平均破壊率の順に並べる |
| タウンホール別の最高レベル | `player/level_caps.dart` | `level_caps.json` の表の `[タウンホール − 1]` の位置の値を使う。0 または表にない場合は表示しない。公式 API の `maxLevel`(ゲーム全体の最大)は使わない |
| 画像の名前 | `player/game_assets.dart` `gameSlug` | 小文字に変換し、`.` と `'` を削除してから英数字以外の文字を `-` に置き換える。例: `P.E.K.K.A` → `pekka`、`Archer Queen` → `archer-queen` |

### 4.4 多言語
- 文言は `apps/mobile/lib/l10n/app_{ko,en,ja}.arb` に置く。英語のファイルが基準(template)である。
- 新しい文言は 3 言語すべてに追加し、`flutter gen-l10n` で `app_localizations*.dart` を生成して一緒にコミットする。
- 数字や名前が入る文言はプレースホルダー(`{n}`、`{used}/{total}`)を使う。

### 4.5 画面の共通ルール
- 本文の幅は `contentMaxWidth`(640) 一つに揃える。並べて表示は `splitViewMinWidth` 以上のときだけ有効にする。
- 一覧画面はプルして更新に対応する。
- 統計のアイコンは Material アイコンのみを使う。
- クラン戦の本文(`WarView`)は、通常のクラン戦とリーグ戦の対戦で共用する。残り時間の文言は 1 分ごとに再描画する。

## 5. ゲームデータと画像のツール (`tool/`)
| スクリプト | 処理 | 生成物 | リポジトリ |
|---|---|---|---|
| `fetch_game_images.sh` | npm パッケージ `clash-of-clans-data`(MIT)から画像を取得し、名前だけ変えてコピー | `apps/mobile/assets/game/<種類>/<名前>.webp` | 含めない(.gitignore) |
| `gen_game_data.sh` (`gen_game_data.mjs`) | 同じパッケージのデータからタウンホール別の最高レベルと分類表を作る | `assets/data/level_caps.json`、`item_groups.json` | コミットする |

- パッケージにまだない新しい装備は、`gen_game_data.mjs` の `EXTRA_EQUIPMENT_HERO` にヒーローを直接記入する。
- 画像がない場合、アプリは画像の代わりに代替表示を行う(FR-17)。
