## 1. テスト方法

### 1.1 自動テストの種類
| 種類 | 対象 | 説明 |
|---|---|---|
| 単体テスト | モデル、計算関数 | 一つの関数に値を入れ、結果が正しいかを確認する |
| サーバーテスト | サーバーのルート | 実際のサーバーを起動せず、リクエスト処理の関数に偽のリクエストを入れて応答を確認する |
| ウィジェットテスト | アプリの画面 | テスト環境で画面を描画し、文字、ボタン、遷移、位置を確認する |

### 1.2 偽データを使う理由
- 公式 API はトークンと登録した IP が必要で、データも常に変わる。そのため、テストでは実際の API を呼び出さない。
- サーバーは `server/test/app_test.dart` の `FakeApi`、アプリは `apps/mobile/test/support/fake_api.dart` の `FakeApi` で決まった応答を返す。
- クラン戦は `war_fixture.dart`(2 対 2 の戦争)、リーグ戦は `cwl_fixture.dart`(3 クラン、3 ラウンド)の固定データを使う。
- リクエスト回数も数える。エラーでも同じリクエストが繰り返されないことを確認するためである(NFR-03)。

### 1.3 実行コマンド
```
cd packages/coc_models && dart analyze && dart test
cd server && dart analyze && dart test
cd apps/mobile && flutter analyze && flutter test
```
`analyze` はコードを実行せずに文法エラーや誤った使い方を見つける静的解析である。

## 4. 手動確認項目
自動テストでの確認が難しい、または実際の環境が必要な項目である。

| ID | 確認内容 | 方法 | 時期 |
|---|---|---|---|
| M-01 | 実際の画面の全体の流れ(検索 → クラン → プレイヤー → クラン戦) | サーバーと Web アプリを起動し、ブラウザで確認 | 機能変更のたび |
| M-02 | ホームの非公式の表記 | Web アプリのホーム画面を確認 | リリース前 |
| M-03 | ダークテーマとシステムテーマの切り替え | 設定でテーマを変えて確認 | リリース前 |
| M-04 | 実際のトークン・IP でサーバーが公式 API を呼び出せるか、アプリのビルドにトークンがないか | サーバー起動後に `curl http://localhost:8080/clans/%232LCQYV0VL`、`curl http://localhost:8080/players/%232PLCLPYV` | サーバー環境が変わるとき |
| M-05 | コミットに `.env`・トークン・ゲーム画像が含まれていないか | プッシュ前に `git status`、`git diff --cached --name-only` | プッシュのたび |
| M-06 | リーグ戦の実データ(順位、ラウンド、メンバー成績、ボタン) | リーグ戦の期間(毎月初め)に、リーグ戦に参加しているクランで確認 | 2026 年 11 月シーズン |
| M-07 | 同点時の「合計破壊率」がゲーム画面の値と同じか | M-06 のときにゲーム画面と比較 | 2026 年 11 月シーズン |

cd server && dart run bin/server.dart
